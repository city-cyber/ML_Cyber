# Соответствие заданию

| Этап | Состояние | Где смотреть |
|---|---|---|
| 1. Сбор и обработка | Реализован; используются easy_ham, hard_ham, spam_2 и внешний контроль | `src/data.py`, `data/processed`, разделы 1–2 ноутбука |
| 2. Обучение модели | Реализован; 5-fold CV, выбор порога, независимые тесты | `src/modeling.py`, `reports`, разделы 3–4 ноутбука |

| 6. Отправка ссылки | Выполняется каждым участником после завершения презентации | Нужны ФИО, группа и доступная ссылка |

Сохранена логика PROJECT_final: `project/PROJECT.ipynb`, `src/constants.py`,
отдельные модули функций, `data/`, `docs/`, README с описанием и результатами.
Папка `microservice` содержит приложение и сохранённую модель с метаданными.

## Материалы для шаблона презентации

- Слайд 8: постановка задачи, вход RFC 822/MIME, метрики и приоритет FP — раздел 0 ноутбука.
- Слайд 9: Dummy, ComplementNB, логистическая регрессия, LinearSVC — раздел 3.1.
- Слайд 10: источники, размер, классы, преобразования — `data_summary.json` и разделы 1–2.
- Слайд 11: выбранная модель, CV, порог, validation — `metrics.json` и `cv_comparison.csv`.
- Слайд 12: test и внешний контроль — `final_comparison.csv` и матрицы ошибок.
- Слайд 13: код — локальный проект; ссылку на репозиторий команда добавляет после публикации.
- Слайд 14: упаковка — `docs/DOCKER.md`, `/docs` работающего API и `reports/docker_api_verification.json`.
- Слайд 15: фактические результаты и ограничения — `RESULTS.md`.
- Слайд 16: мультиязычность, concept drift и полуобучение — раздел 5.2 ноутбука.

ФИО и номер группы не выдумываются. Имя итоговой командной презентации следует
оформить по правилу задания после получения этих данных.
