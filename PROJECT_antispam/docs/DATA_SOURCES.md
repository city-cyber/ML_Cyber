# Данные и правила обработки

Обучающие данные читаются из соседних папок `../easy_ham`, `../hard_ham`, `../spam_2`.
Вложенные одноимённые каталоги поддерживаются. Оригинальные файлы не изменяются.
AppleDouble и `__MACOSX` являются метаданными и не считаются письмами.

Это три подкорпуса одного SpamAssassin. Независимых LingSpam или SpamBase в проект
не добавляли: текущая версия строится на явно указанных пользователем данных.
Использование нескольких независимых источников остаётся возможным улучшением.

Первичный источник и описание:

- https://spamassassin.apache.org/old/publiccorpus/
- https://spamassassin.apache.org/old/publiccorpus/readme.html

В описании есть историческая правка ошибочно размеченного spam-письма от 11.03.2005.
Загрузчик исключает его, если оно присутствует в старой версии корпуса; текущая локальная
копия этого файла не содержит. Права на тексты сохраняются у авторов писем.

Контрольный набор задания:

- https://disk.yandex.ru/d/mJ_9zG3dX3eZgg
- Имя: `test_task_emails.tar.xz`.
- Размер: 1 925 712 байт.
- SHA-256: `14ccf52ab11673a85acab7c9793effa2c8db72c61838ba1b15356bd22d9576ee`.
- Классы берутся из каталогов `ham` и `spam`.

Для воспроизводимости архив сохранён в `data/external/`. Первичная загрузка
не требует OAuth, используется публичный API Яндекс Диска. После скачивания сеть
для обучения не нужна. Парсер читает контрольные .eml непосредственно из архива:
это исключает зависимость от поведения ОС при чтении отдельных распакованных файлов.

Обучающие письма, совпадающие с любым письмом контроля по исходным байтам,
нормализованному тексту/телу или Message-ID, исключаются **до разбиения**.
Внутри корпусов дубликаты исключаются, конфликты меток отправляются в аудит.
Для основного внешнего контроля применяется та же очистка, а метрики по полному
архиву сохраняются отдельно. Пустые тексты полного архива классифицируются
по нулевому TF-IDF-вектору, но не включаются в очищенный набор.

Точные размеры, доли и причины исключений содержатся в
`data/processed/data_summary.json` и `data/processed/data_audit.csv`.
Подробный EDA использует только train. Тестовые метки не участвуют в fit,
выборе модели или выборе порога.
