# Итоговое задание: антиспам-классификатор

Основная работа — [`project/PROJECT.ipynb`](project/PROJECT.ipynb).
Ноутбук содержит выполненный эксперимент с таблицами, графиками и выводами на русском языке.
Краткие фактические результаты — [`docs/RESULTS.md`](docs/RESULTS.md).

## Задача и границы

Подготовить данные и обучить бинарный классификатор писем `ham/spam`, уделив
особое внимание ложным блокировкам обычной почты. Реализованы этапы 1–3:
подготовка данных, обучение и упаковка в FastAPI + Docker. Публичное размещение отложено.
Исходные почтовые данные не изменяются.

## Запуск готового сервиса

Из папки проекта в PowerShell при запущенном Docker Desktop:

```powershell
.\start_docker.cmd
```

Скрипт соберёт образ `project-antispam:latest`, запустит контейнер и дождётся healthcheck.
Swagger: **http://127.0.0.1:8000/docs**. Готовый образ можно запустить командой
`.\start_docker.cmd -SkipBuild`; другой порт — `.\start_docker.cmd -Port 8080`.
Остановка: `.\stop_docker.cmd`. Обёртки `.cmd` запускают PowerShell-скрипты
с разовым разрешением выполнения без изменения системной политики Windows.

Подробные команды, примеры JSON и `.eml`: [`docs/DOCKER.md`](docs/DOCKER.md).

За основу оформления взята структура образца: последовательные разделы загрузки,
предобработки, подробного EDA, сравнения моделей, итоговой оценки и выводов.
Анализ текстов включает баланс классов, пропуски и дубликаты, распределения длины,
HTML/MIME, ссылки, парные графики, корреляции, характерные слова и статистические тесты.

## Данные и защита от утечки

Три обучающих подкорпуса принадлежат SpamAssassin: это несколько наборов одного семейства,
а не три независимых источника. Подробнее — [`docs/DATA_SOURCES.md`](docs/DATA_SOURCES.md).
Контроль взят по ссылке из задания; метки определены каталогами `ham` и `spam`.

- Служебные файлы macOS и индексы не считаются письмами.
- Для модели используются только декодированные тема и тело; `X-Spam-*`, `Received`,
  отправитель, название корпуса и имя файла в признаки не входят.
- Проверяются совпадения исходных байтов, нормализованного текста/тела и `Message-ID`.
- Все пересечения с полным внешним контролем удаляются из обучения до разбиения.
- Подробный EDA использует train; TF-IDF обучается внутри каждого CV-фолда.
- Конфликты меток и все исключённые строки отражены в аудите.

Разбиение примерно 60/20/20 со стратификацией по источнику, seed=42.
Модель выбирается по пятикратной CV внутри train. Порог выбирается только на validation.
После фиксации порога модель не переобучается на validation/test.

## Модели и метрики

Сравниваются Dummy, ComplementNB (два значения alpha), LogisticRegression
(два значения C, повышенный вес ham) и LinearSVC. Векторизация — TF-IDF слов
и биграмм, до 30 000 признаков, с сублинейной частотой слов.

Оцениваются Precision, Recall, F1, F0.5, FPR, FP/FN, ROC-AUC и average precision.
Для порога заданы ограничения validation: Precision ≥ 99%, FPR ≤ 1%, TP > 0.
Среди допустимых порогов минимизируется FP, затем максимизируется Recall.
Строгая политика может существенно снижать полноту — обе политики показаны в отчёте.
Интервал FPR отражает ограниченность вывода даже при нуле наблюдаемых FP.
